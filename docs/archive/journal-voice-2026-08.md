## 38. ★★アプリ全体の方針転換とJournalの作り直し(2026-08-11)

### 38.1 これからのデザイン言語・体験の構造(ユーザー明言)

- **デザイン言語**: テクスチャを排除し、ベタ塗りの色面・直線・円などの
  **バウハウス調の純粋幾何学ミニマリズム**に統一する。
- **体験の構造**: デジタル特有の「物理的な手触り」を重視する。3つのアプリが
  それぞれ独自の物理メタファーを持つ:
  - **Journal** … 音声の抽出(テープを巻き、切り出す)
  - **Task** … 落下と粉砕
  - **Explore** … 立体の展開と結合
- **最終出力(Log)**: 1日の終わりにこの3要素が1つのキャンバス上で物理的に
  プレス(次元圧縮)され、**1枚の継ぎ目のない幾何学ポスター**として統合される。

→ Task の「落下と粉砕」、Explore の「立体の展開と結合」、そして Log の
プレスはまだ未着手。今回は Journal だけを作った。

### 38.2 Journal(声の記録)の作り直し

`components/VoiceStudio.tsx` を新設し、これ1つで完結させた。ジャーナルの
RECORD タブも、タブバーからのオーバーレイも**同じ部品**なので、見た目と
操作が構造的に一致する。

- **配置**: 画面の下部に、画面をはみ出すほど**巨大な円が2つ**(カセットの
  リールの抽象)。中心を画面の外(x = -2% と 102%)に置いてあるので、半分弱
  しか見えず、下端でも切れる。2つの円のあいだは**テープを表す直線の帯**が
  ピンと張ってつながる。その上の空間に波形とタイポグラフィ。
- **録音中**: 2つの円が回り(`vs-reel-spin`)、帯の縞が流れる(`vs-tape-run`)。
- **操作はトグル**: 上の空間をタップで開始、もう一度タップで停止。長押しでの
  録音(以前のトランシーバー式)は**廃止**。
- **止めても送らない**: `review` 状態で待つ。**送信 / キャンセル**を明示的な
  ボタンで出す。
- **トリミングダイヤル**: 停止後、同じ2つの円が物理ダイヤルになる。左を回すと
  波形の**始点**、右を回すと**終点**が動く。1回転で全体の50%だけ動く重い比率
  (`TURN_RATIO`)にしてあり、15度ごとに手応えを返す(`NOTCH`)。
  波形は範囲外が薄く落ち、縦の直線で始点・終点を示す。
- **実際に切る**: `lib/audioTrim.ts` を新設。`AudioContext.decodeAudioData` で
  生の波形へ戻し、必要な範囲だけを16bit PCMのモノラルWAVへ組み直して送る。
  デコードできない端末では**元の音声をそのまま送る**(トリミングは効かないが
  記録は失われない)。
- **グローバル録音**: タブバー**右端の丸ボタンを録音アイコンに変更**し、3つの
  アプリすべてで常設にした。押すと画面が暗くなり(`VoiceOverlay`、body直下へ
  createPortal)、同じUIがオーバーレイで出る。

### 38.3 ★実装で踏んだ落とし穴(次に触るときのために)

1. **オーバーレイが一度も出なかった**: 「開いていて state が idle なら閉じる」
   と書いたため、開いた瞬間(まだ録音していない = idle)に閉じていた。
   `sending → idle` という**遷移**を見ること(`prevRecStateRef`)。
2. **送信/キャンセルのボタンが円に重なっていた**: 絶対配置で円の上に置いて
   いた。必ず上のブロック(タップ領域)の**中**に入れること。
3. **円の「抜き」の色は背景と完全に一致させる**: リールのハブ・スポーク・輪は
   背景色で塗って穴に見せているため、色がずれると縁に段差が出る。幕
   (`VoiceOverlay`)は半透明+ぼかしをやめ、**不透明の `SCRIM`** にして、
   抜きの色を同じ値にした。インラインのときは `BD_LIGHT`(ジャーナルの地)。
4. **波形とトリミングは React の外へ**: 音量の並びは `levelsRef`(ref)に貯め、
   canvas へ rAF で描く。トリミングの位置も `trimRef` に持ち、指の動きで
   setState しない。§14 で潰した「毎フレーム全タブが再レンダーされる」穴を
   踏まないため。実測(4倍スロットリング・本番ビルド)で、横スワイプ **0ms** /
   録音中2.5秒 **0ms** / ダイヤルのドラッグはドラッグ開始時の1回だけ113ms。
5. **ハプティクスの限界**: `haptic()` は `navigator.vibrate` で、**iOS Safari は
   このAPIを持たない**。ユーザーの実機(iPhone)では手応えは返らない。
   「重みのあるハプティックフィードバック」は Android と対応ブラウザでのみ
   効く。実機で手応えが要るなら、この方式では実現できないことを先に伝える。

## 40. ★ダイヤルが一切操作できなかった原因と、その修正(2026-08-11続報)

ユーザー報告:「円が操作できません。操作できるような見た目でもない、背景の
ように見える。操作するには円が上によりすぎています。少し小さくし、もう少し
下側に配置してください。円の縁に計5つほど短く、細くない線を入れて回転して
いるのが分かるようにしてください。円はダイヤルのような役目だと思ってください」

### 40.1 ★操作できなかった原因(自分のテストがすり抜けていた)

「タップで録音を開始/停止する」ための舞台(stage)の div が、円の**上**に
重なっていて、円へのポインタをすべて吸っていた。円は一度も指を受け取って
いなかった。

**なぜ検証をすり抜けたか**: §38 の検証でダイヤルを回したとき、掴んだ点が
たまたま舞台の下端より**下**(y=790、舞台は y<738)だったため、そこだけは
円に届いていた。実機で人が触るのは円の見えている本体(画面の中ほど)で、
そこは舞台の内側なので必ず吸われる。**「動いた」ことだけを確認して、
「人が触る場所で動くか」を確認していなかった**のが検証の穴。

**修正**: 重なり順とポインタの通し方を明示した。
- 円 … `zIndex:1` / `pointerEvents: review ? "auto" : "none"`
- 舞台 … `zIndex:2` / `inset:0`(全面)/ `pointerEvents: canToggle ? "auto" : "none"`
- 最下部のバー … `zIndex:3`
録音していないときは舞台が全面で指を受け(どこをタップしても録音が始まる)、
切り出し中(review)は舞台が指を素通りさせて円が受け取る。**どちらの状態でも
「触れる要素」がちょうど1つになる。**

検証: ダイヤルの実際の `getBoundingClientRect()` から**可視部分の中ほど**
(390x844 で (77, 663))を掴んで回し、`data-rot` が 0 → 2.000rad になることを
確認した。以後この手のテストは、要素の実座標から掴む点を計算すること。

### 40.2 大きさと位置

画面いっぱい・縦中央だったのをやめ、**小さく・下へ**動かした。
- `DIAL_RATIO` 0.86(直径 = 器の幅の86%。以前は 1.94)
- 中心x = ∓6%(左右へはみ出す)
- 中心y = 器の下端から直径の30%上 → 円の見えている帯が画面の下40%に来る
文字と波形はダイヤルより上の空間の真ん中へ(`paddingTop:84` で見出しぶんを
避ける)。

### 40.3 縁の目盛り

## 41. 円を大きさごと戻す・波形と数字の役割を分ける・入場と操作の反応(2026-08-11続報)

ユーザー指定7点への対応。

1. **円は前の大きさ(直径=器の幅の1.94倍)へ戻した**。ただし中心の高さは
   下寄り(§40)のまま。砂時計の腰=いちばん内側まで来る所が親指の届く高さに
   来る。
2. **数字は強調しない**。録音中は 19px・字間0.20em・控えめな色で置くだけ。
3. **録音を終えたときだけ、幾何アルファベット**(`components/GeoType.tsx` =
   このアプリ固有の書体)で長さを大きく出す。コロンは正方形2つで組んだ。
   ★この書体の数字は**装飾的で、読み取りやすさは高くない**(円と角丸の
   ブロックに見える)。読める数字は下記4の「円の上の秒数」が担っている、
   という役割分担にしてある。
4. **切り出し中は、それぞれの円の上にその位置の秒数**を出す(左=始点、
   右=終点)。掴んでいる側は色が濃くなる。
5. **波形を太く・両端を丸く**した(間隔9px・太さ5px、`lineCap:"round"` で
   塗りではなく線で描く)。
6. **円が左右から入ってくる**(`vs-dial-in-l` / `vs-dial-in-r`、640ms)。
   画面を開いたときと録音を始めた瞬間に流す。★`animation-fill-mode` は
   **backwards**。both にすると最後のコマの transform が残り続け、切り出しの
   ときに JS が書く rotate() を上書きしてしまう(§21 と同じ罠)。
7. **目盛りは一番端へ寄せ、小さく**した(長さ=直径の4.5%、太さ1.46%)。

### 41.1 ★性能: Layout が毎フレーム走っていた(508ms → 0ms)

円を5倍の面積に戻した直後、ダイヤルのドラッグが **92ms → 640ms**(4倍
スロットリング・同一スクリプトでの前コミットとの比較)に悪化した。

**遠回りした過程を残す**: canvas の再描画・transform の書き込み・テキスト
選択・haptic・背景色の遷移を**1つずつ**外して測ったが、どれを外しても
600ms 前後のままだった。原因が1つだと思い込んで1つずつ潰したのが誤りで、
**実際は複数の原因がそれぞれ単独で同じくらいのコストを持っていた**ため、
1つ外しても数字が動かなかった。

`Tracing`(devtools.timeline)でイベント種別ごとに集計して決着した:
```
1101ms RunTask / 508ms Layout / 30ms Paint / 9ms RasterTask
```
**Paint ではなく Layout**。犯人は2つ:
- `textContent` への代入を毎フレームやっていた(**値が同じでも**要素の
  レイアウトを汚す)。巨大な円を含むページなのでレイアウトが高い。
  → 同じ文字列なら書かない(`setText`)。
- 円の上の秒数に `transition: font-size` を掛けていた。**font-size の遷移は
  遷移中ずっとレイアウトを走らせる**。→ 太さと色だけで反応を出す。
あわせて `data-rot` の毎フレーム書き込みもやめた(指を離した時に1回だけ)。

結果、**ドラッグの long task は 0ms**、Layout はトレースの上位から消えた。

**教訓**: 描画が重いときは Paint を疑いがちだが、**まず Layout かどうかを
トレースで確定させる**。そして「1つずつ外して数字が動かない」ときは、
原因が1つではない可能性を先に疑うこと。

### 41.2 副作用として捨てたもの

掴んだ反応は当初「円の塗りを一段明るくする」だったが、直径が画面幅の約2倍
あるため、背景色を変えるだけで巨大な面が塗り直され、`transition` を付けると
それが十数フレーム続く。**塗りは変えず、目盛りの色・円の上の数字の色**で
反応を出す形にした。

検証: `tsc` / `eslint`(既知の`<img>`警告3件のみ)/ `build` 通過。Chromium
(390x844・本番ビルド)で、入場アニメーションの途中・録音中・切り出し中・
掴んだ瞬間をスクリーンショットで確認し、ダイヤルの回転(0→1.60rad)と
左右の秒数表示・掴んだ側だけ濃くなる反応を確認した。性能は上記のとおり。
**WebKit実機での最終確認は未実施。**

## 42. 円を白へ寄せる・カセットの物理キー(REC / RESET / SEND)を新設(2026-08-11続報)

控えめな明度差を最初は忠実に採ったが、実機では背景と区別が付かなかった。

### 42.2 カセットプレイヤーの物理キー(`TransportKey`)

最下部のバー(✕ / ラベル / ✓)をやめ、**出っ張りのある3つのキー**にした。
```
   REC        RESET       SEND
 (赤い輪)   (金のランプ) (緑のランプ)
```
- キーは「穴(well)」の上に浮いた「面(cap)」の2枚組。押されていないときは
  面が `translateY(-6px)` して浮き、穴が影として見える。押すと沈む。
- **状態の対応**
  - idle … REC だけ浮いて押せる。RESET / SEND は沈んだまま暗く、ランプも消灯。
  - recording … REC が**押し込まれたまま**(カセットの録音キーと同じ)。
  - review … 3つとも浮き、RESET(金)と SEND(緑)のランプが灯る。
  - sending … SEND が押し込まれる。
- REC は review 中も押せる。押すと新しい録音が始まる(=録り直し)。
- RESET は切り出しの範囲を全体へ戻し、**ダイヤルの角度も0へ戻す**。
- ★キーの色は **すべて不透明**にすること。半透明にすると、明るい円の上と
  地の上とで見え方が変わり、物として読めなくなる(最初 rgba で作って失敗)。

オーバーレイの「閉じる」は、キーの列と混ざらないよう左上の ✕ へ移した。

検証: `tsc` / `eslint`(既知の`<img>`警告3件のみ)/ `build` 通過。
Chromiumで各状態のキーの `transform` と `disabled` を実測:
idle=REC(-6px,有効)/RESET・SEND(0px,無効)、recording=REC(0px)、
review=3つとも(-6px,有効)。ダイヤルを1.80rad回してから RESET を押すと
0.00 へ戻ることも確認。性能(4倍スロットリング)は横スワイプ0ms・録音中0ms・
ダイヤルのドラッグ100ms で回帰なし。**WebKit実機での最終確認は未実施。**

## 43. 数字の存在感を落とす・ダイヤルに惰性・CANCELキー・閉じるを右上へ(2026-08-11続報)

ユーザー指定8点への対応。

1. **真ん中の数字は幾何アルファベットをやめた**。「もっと存在感をなくして」

8. **オーバーレイのときは円の腰を画面の真ん中あたり**(`h * 0.54`)に置く。

検証: `tsc` / `eslint`(既知の`<img>`警告3件のみ)/ `build` 通過。Chromiumで:

## 44. キーを丸く・掴むと円がふくらむ・タブとオーバーレイの円を一致・

   タブバーの位置が他タブとズレていた)。
6. **波形の中心線を出した**。★高さゼロの棒は描かない。丸い端

   中心線が数珠つなぎに見えていた。
7. **録音を始めたときの円の変な挙動**。入場アニメーション(`vs-dial-in-*`)を
   録音開始でも流していたため、`getUserMedia` の許可待ちのぶん遅れて
   再生され、しかも同時に回転が始まっていた。**入場は mount のときだけ**に

### ★あわせて直した2つの取りこぼし(検証で発見)

- **操作キーの帯が、その下のダイヤルへの指を吸っていた**。帯は画面幅

### ★検証スクリプトの注意(次に書く人へ)

たまたま合っていたので気づくのが遅れた)。正しくは:
- 見えている列を `getBoundingClientRect().x ≈ 0` で特定し、

  英語(RECORD 等)は表示テキストであって label ではない。

## 46. 円をさらに小さく・波形を「録音中は狭く/停止で全体表示へ」・カクつきと
ちらつきの解消・RESET を PAUSE に(2026-08-11続報)

参考画像(ボイスメモ系アプリ)とともに4点の指定。

1. **円をさらに小さく、中心同士も近づけた**。直径 1.48→**1.30**、中心のx
   0.39→**0.30**(砂時計の腰は 0.30 のまま)。実測: 直径 577→**507**、
   中心間 694→**624**。左円が画面に見えるのは y 199..650 で、キーの列の
   上端 677 とは重ならない。

2. **波形を2つのモードに分けた**(`components/VoiceStudio.tsx` の `draw`)。
   - **録音中**: 帯を「腰の少し上」(`WAVE_DY` = -136)に置き、**円に絶対に
     重ならない幅**までしか広げない。幅はコードが円の式から出す:
     中心から dy 離れた高さの隙間 = `(cxR-cxL) - 2*sqrt(R²-dy²)`。帯の上下の
     うち中心に近い方で決まる。実測で帯は x 119..271、左円の右端は 76/113 →
     重なり無し。赤い線を `REC_LINE_AT`(0.66)の位置に立て、録れた棒はその
     左へ流れ、線の右は点線(まだ録っていない)。棒は録音中だけ細かい
     (pitch 5 / 太さ 3)。
   - **停止すると**帯が幅・高さとも広がり(`SPLIT_MS` 420ms の CSS 遷移)、
     真ん中の1本が**左右2本へ分かれて**全体表示＝トリミングになる。
     分かれ具合は `splitRef`(0→1、ease-out)を rAF が読んで描く。
     ★state にすると毎フレーム全体が再レンダーされるので ref。
   - 帯は flex の並びから外し**絶対配置**にした。幅を遷移させても周りを
     レイアウトし直さずに済む。

3. **★「カクカクする・画面がちらつく」の原因を2つ特定して直した**。
   - **カクカク**: 波形は `LEVEL_MS`(45ms)ごとにしか増えないのに、棒を
     配列の添字だけで置いていたため、1本ぶん(5px)ずつ**飛んで**いた
     (≒22fps)。経過時間から「次の1本までの端数」を出し、
     `shift = (elapsed % LEVEL_MS) / LEVEL_MS * BAR_PITCH` だけ全体を
     ずらすようにした。60fps で連続して流れる。Chromium で連続10フレームの
     canvas をハッシュ化し、**10/10 すべて異なる**ことを確認。
   - **ちらつき**: (a)経過時間を100msごとに state へ入れていて、そのたびに
     スタジオ全体が再レンダーされていた(時間は rAF から textContent で
     書いているので、この state はそもそも不要だった)。撤去。
     (b)`ResizeObserver` の中で毎回新しいオブジェクトを `setSize` していた
     ため、帯が広がる間ずっと1フレームごとに再レンダーされていた。値が
     同じなら更新しないようにした。**録音中の React の再レンダーは0回**になった。

4. **RESET を PAUSE に変えた**(ユーザー指定)。`MediaRecorder.pause()/
   resume()` で、もう一度押すとそのまま続きから録れる。
   - 一時停止をまたいでも長さが正しくなるよう、`recordedRef`(確定済み)と

## 47. ★波形のガクつき・点滅の真因(等間隔配置)を解消・待機中の横線を撤去・
CANCEL で本当に初期状態へ戻す(2026-08-12)

1. **★ガクつき・点滅の真因**: 棒を「本数を数えて等間隔」に置いていた
   (`x = lineX - k * BAR_PITCH`)。ところが波形を測る `setInterval(45ms)` は
   **45msちょうどでは来ない**(端末や負荷で40〜70msに揺れる)。前回入れた
   「次の1本までの端数(`elapsed % 45`)でずらす」補正は、この揺れとは
   別の時計(経過時間)から出しているため、実際に棒が増える瞬間と位相が
   合わず、増えるたびに最大1本ぶん飛ぶ。これが「ガクガク」と「点滅」の
   正体だった(前回の修正が効かなかった理由でもある)。
   **対応**: 測った瞬間の時刻を `timesRef`(録音の経過ms)に一緒に記録し、
   描くときは `x = lineX - (now - times[k]) * (BAR_PITCH / LEVEL_MS)` と
   **時刻から実際の位置を出す**。間隔が揺れても位置は常に連続で、1フレーム
   ぶんも飛ばない。一時停止中は経過が進まないので棒もその場で止まる
   (壁時計を使うとここで勝手に流れてしまう)。
   検証: 連続12フレームで棒の重心を測り、124.10→123.89→123.70→…→121.85 と
   **単調かつ等速**(飛びが1つも無い)ことを確認した。
2. **波形の canvas を自分だけの合成レイヤーへ**(`willChange:"transform"` +
   `translateZ(0)`)。以前は毎フレームの描き直しが**巨大な円と同じレイヤー**を
   汚し、円ごと塗り直しになっていた(点滅の一因)。
3. **待機中の横線を撤去**。何も録っていないとき(`levels` が空)は canvas に
   **何も描かない**。以前は中心線だけが残り、円の上を横切って見えていた。
   あわせて canvas 自体も `opacity:0` / `scaleX(0.5)` にしておき、**録音を
   始めると横に伸びながら現れる**ようにした(実測: opacity 0→0.47→0.76→
   0.98→1.00、scaleX 0.5→0.91→0.98→1.00)。
   ★待機中の寸法は「全体表示」ではなく**録音中と同じ**にしておくこと。
   全体表示の寸法にすると、録音を始めた瞬間に幅が 338→152 へ縮む
   アニメーションが走ってしまう。
4. **★CANCEL で本当に初期状態へ戻るようにした**。2つの穴があった。
   - `useVoiceRecorder.cancel()` が、**録音中**の経路で `levelsRef` を
     消していなかった(review の経路だけ消していた)。どの状態から取り消しても
     波形・長さ・音声をすべて捨てるようにした(`durationMs` も0へ)。
   - より根本的に、**取り消しても canvas が描き直されていなかった**。
     rAF ループの effect の依存が `[drawAll, recording, active, coasting,
     splitting, size]` で、review→idle では `drawAll` の参照も `recording` も
     変わらないため effect が動かず、前の録音の波形が残ったままになっていた。
     依存に `state` を足した。
   検証: 録音→停止→CANCEL で canvas の不透明ピクセルが 12016 → **0**、
   もう一度録音すると 1140(新しい棒だけ)になることを実測。

検証: `npx tsc --noEmit` / `npx eslint .`(既知の`<img>`警告3件のみ) /
`npm run build` すべて通過。性能(4倍スロットリング・本番ビルド):
横スワイプ **0ms** / ダイヤルのドラッグ 146ms(前回 155ms) /
録音中 64+181ms。録音中のトレース内訳は Layout 150ms(前回 176ms)で、
器が親からはみ出す構成に由来する既知のぶん(§44)。

**WebKit実機での最終確認は未実施。とくに (a) ガクつき・点滅が実機でも
消えたか、(b) PAUSE→再開した録音が正しく1本に繋がっているか、は実機でしか
答えが出ない。**

## 48. 入場アニメーションがアプリ復帰で流れない・待機中でも円を回せる・

   マウント時に1回だけ流していたが、**3つのアプリの列は常にマウントされた

     円の式で判定して振り分ける**(`dialAt`)。円自身は `pointerEvents:none`。

## 49. 反応する場所を REC と円だけに・遷移中は円を出さない・マイクの解放・
トリミングでも帯を広げない(2026-08-12)

1. **録音の開始/停止は「REC キー」と「円の上」だけ**(ユーザー指定)。
   舞台は画面いっぱいのままだが、`onPointerDown` で指を下ろした場所が円の
   上だったか(`onDialRef`)を覚えておき、click ではそれが真のときだけ
   `voice.toggle()` する。腰の余白や上の空きは何も反応しない。
2. **★アプリ遷移の入場アニメーションがおかしい件**。遷移の途中で円が
   既に定位置に見えているのに、そこから外へ飛んで入り直す見え方になっていた。
   **見えていない間は円をそもそも描かない**(unmount)ようにして解決。
   ★合図は **AppShell から渡す prop**(`AppColumn` の `active` を RecordTab
   経由で `VoiceStudio` へ)。最初は IntersectionObserver で見え方から推測
   したが、**実機では一度も閾値に達せず「円が出てこない」不具合になった**
   (Chromium では動いていた)。どのアプリを表示しているかは AppShell が
   知っているので、推測せずそれを使う。オーバーレイは開くたびに新しく
   マウントされるので既定 true。
   実測: 隣へ払っている最中は円のdivが0個、戻ると入場が 50→633ms と進む。
3. **★マイクが録音していないときも点いたままになる件**(実機・Safari で
   マイクを常時許可した状態)。原因になりうる穴を3つ塞いだ。
   - **生ストリームを自分で持つ**(`streamRef`)。以前は `rec.stream` 経由で
     しか止めておらず、MediaRecorder を作る前に例外が出ると止め損ねていた。
   - **二重起動の防止**(`startingRef` と `recRef` の確認)。素早く2回叩くと
     `getUserMedia` が2つ走り、後から来た方だけが `recRef` に入って、先に
     取ったストリームが誰にも止められず点きっぱなしになる。
   - **`onstop` が来なかったときの保険**(1500msのタイマーで必ず手放す)。
     Safari で `onstop` が落ちる報告があるため。
   どの終わり方(停止・録音中のキャンセル・送信後・例外・アンマウント)でも
   `releaseStream()` を必ず通す。
   検証: `getUserMedia` を包んで取得したトラックを全部覚えておき、
   録音中は live 1、停止後・CANCEL後・録音中のCANCEL後はいずれも **live 0**
   になることを実測(トラックが増えっぱなしにならないことも確認)。
4. **トリミングでも帯を広げない**(ユーザー指定)。`WAVE_H_ALL`(104)と
   `waveWAll`(338)を廃し、録音中と同じ `WAVE_H`(58)/`waveW`(実測152)を
   常に使う。棒の刻みも `BAR_PITCH`(5)/`BAR_W`(3)に一本化した。
   中心の1本が左右2本へ分かれる演出(`splitRef`)はそのまま。
   ※この項目は一度「広げるままでよい」と取り下げられて戻したが、再度
   「やはり広がらないように」と指示があり、こちらで確定。
5. **★オーバーレイの下端に明るい帯が残る件**(実機)。幕は
   `position:fixed; inset:0` だが、端末の事情(セーフエリア等)で下端まで
   届かないことがある。**html の地色も幕の色(`DIM_GROUND`)にする**ことで、
   届かなかった所に出る色を合わせ、隙間そのものを見えなくした(閉じるときに
   元の色へ戻す)。あわせて幕に `height:100lvh`・背景色を明示し、幕の中の器は
   割合の高さをやめて `position:absolute; inset:0` で埋め切るようにした。
   タブの中で気づかなかったのは、そちらの地色が html と同じだったから。

検証: `npx tsc --noEmit` / `npx eslint .`(既知の`<img>`警告3件のみ) /
`npm run build` すべて通過。性能(4倍スロットリング・本番ビルド):
横スワイプ **0ms** / 録音中 **0ms** / トリミングのドラッグ **0ms**。
