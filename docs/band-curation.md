## 1. 全体の形 ―― 3段

```
① 集める（コード・AIなし） → ② 選ぶ（AI） → ③ 見せる（コード）
```

**AI にやらせるのは②の「選ぶ」だけ。** 候補を作る・消す・数を数える・壊れた出力を捨てるのは
全部コード（`briefPipeline` と `taskSuggest` と同じ分担）。AI が止まっても③は①の並びで出る。

## 2. ① 集める ―― 候補の池（最大 40 件）

| 出どころ | 何が入るか | ここで落とすもの（ルール） |
|---|---|---|
| Explore のストック（`items`） | 行きたい所・展示など | **今日もう閉まっている**（`todayPick` の時間帯の表）・会期切れ |
| Explore の未読（`generatedDecks`） | 新しい提案 | 写真の無いもの（第124巡）・会期切れ |
| 日付の無いタスク | いつかやること | 完了済み |
| 声の候補（`inbox`） | 話した中から出たタスク | 承認・却下済み |
| **準備タスク**（`Task.suggestions`） | 近い予定の前に済ませること | 親が完了・親の期日が過ぎた |
| ニュース（`/api/news`） | 見出し | 30分より古い |

各候補は同じ形にそろえる … `{ id, 種類, 題, 期日・時刻, ジャンル, 出どころ }`。
★**今日の山にもう居るもの**（今日の予定・今日へ割り当てた提案）は候補に入れない（二重に出さない）。

### ★準備タスクを動かし直す（①の前提）

- **呼ぶ時** … アプリを開いた時に「期日が 14 日以内・まだ提案を作っていない（`suggestedAt` が無い）」
  タスクを**1回に3件まで**頼む。タスクを作った・日付を付けた時にもその1件を頼む。
- **中身** … 今の `lib/taskSuggest.ts` をそのまま使う（材料 ＝ タスク本体・`me/patterns.md` の傾向・
  過去に済ませた似たタスク）。
- ★**「当日の場所までの時間の確認」**は、今の `Task` に**場所の欄が無い**ので、AI は
  「出発時刻を決める」までしか言えない。本当の所要時間を出すには、タスクに場所を持たせて
  地図の API で測る段が要る（次の段階）。
- ★プロンプトを変える場合は、**文面を先に見せて承認を取る**（今回は変えない前提）。

## 3. ② 選ぶ ―― AI への渡し方

- **場所** … サーバーの新しい口 `/api/curate-band`（鍵はサーバーだけが持つ）。
  モデルは他の機能と同じ Gemini の軽いモデル（`callGemini` を再利用・JSON で返させる）。
- **渡すもの**
  1. いま … 日付・曜日・時刻・時間帯（朝／昼／夕／夜）
  2. 今日の山 … 今日の予定（題・時刻）
  3. この先 7 日の予定 … 題・日付（準備が要るかの判断材料）
  4. 候補の池（①の 40 件。id と短い事実だけ）
  5. この人 … 好みの語（`profile.interests`）・傾向（`me/patterns.md`）・ゴール
  6. 最近の手つき … 直近 14 日の「残した／飛ばした／済ませた」を種類ごとに数えたもの
- **プロンプトの案**（★承認待ち。第2稿。第1稿はユーザーに差し戻された ――「**何を指しているのか
  分からない前置き・本題と関係ないコンテクストが多すぎる**」「**すぐ動けるものではなく、条件を
  加味したおすすめを提案として**」「**どんな材料を与えて、何を推測させるのかだけに絞る**」）

```
次の材料から、この人にいまおすすめしたいものを候補の中から選び、
それぞれ「なぜいまおすすめなのか」を書いてください。

# 材料
<いま>: 日付・曜日・時刻
<予定>: 今日とこの先7日のタスク（題・日付・時刻）
<好み>: 好みの語
<傾向>: 手配を忘れる・後回しにするなどの傾向
<最近の反応>: 直近14日に、残した・飛ばした・済ませたものの数（種類ごと）
<候補>: id・種類・題・事実（期日・会期の終わり・行ける時間帯・どの予定の準備か）

# 選び方
- 時刻・曜日・予定・好み・傾向・最近の反応を合わせて、この人がいまやると良いと思うものを選ぶ。
- 候補の id だけから、最大5件。おすすめの強い順に並べる。
- 理由は材料から言えることだけで、20字前後の1文。

# 出力
JSON の配列だけ。各要素は id と why。選ぶものが無ければ []。
```

- ★★**プロンプトから外したもの（コードが持つ）** … 種類の偏りの上限（提案は2件まで）・
  知らない id と重複の除去・足りないときの補充。★材料に無い事実（営業時間・天気など）を
  書かないことは「材料から言えることだけ」の1行に畳んだ。
- **返ってくるもの** … `[{ id, 段, 理由 }]`
- **コードの検品** … 知らない id・重複を捨てる／種類ごとの上限（提案 2・ニュース 4）／
  足りなければ①の並び（今の規則）で埋める。

## 4. いつ選び直すか・費用

- **選び直す時** … アプリを開いた時に、次のどれかなら ―― 前回から 60 分たった／時間帯が
  変わった／候補の池の中身が変わった（タスクを足した・済ませた等）。
- **結果は端末に保存**（`AppState` には入れない ―― 自分のデータではなく、古くなっても壊れない）。
- **呼ぶ回数** … 1日 5〜8 回。1回の入力は候補 40 件で数千トークン。軽いモデルなので
  費用はごく小さい（正確な額は Google の料金表で確かめる）。
- **失敗・通信なし** … ①の並び（今の規則）でそのまま出す。帯が空になることは無い。

## 5. ③ 見せる ―― 帯（A3 ＋ 止まって送る）

- **段は2つ** … 上 ＝ AI が選んだ「いま」（提案・タスク・準備タスク・声の候補が混ざる）／
  下 ＝ ニュース。
- **見た目**（第133巡にユーザーが A3 を選んだ）… 地の面 ＋ 墨の 1px の輪郭・墨の字。
  写真のある提案は写真の丸。★**写真が無いときは、ピルの左に種類の色の小さな丸**
  （タスク ＝ オレンジ・提案 ＝ 黄・声 ＝ 青。ユーザー指定）。色が大きく出るのは山だけ。
- **動き** … **5 秒止まる → 0.4 秒で 1 つ左へ送る**。2つの段は **2.5 秒ずらす**（同時に動かない）。
  触っている間は止まる。引き下ろし（日付の割り当て）・ニュースの札は今のまま。

## 6. 図形の大きさ ―― 正方形の格子（★提案・承認待ち）

ユーザー指定「**図形の大きさと形は、それぞれで勝手に調整するのではなく、デザインシステムを
統一。正方形のグリッドを設定して、提案やジャーナルは2段2列、タスクは一段4列、日付は一段3列…**」。

- **1マス ＝ 山の幅 ÷ 5**（390 幅で 71.6px ＝ いまの日付の板の高さとほぼ同じ）。混む日は1マスごと縮む。
- **図形の外枠は必ずマスの整数倍** … 提案 2×2／ジャーナルの円 2×2／日付 3×1／
  タスク 2×1・3×1・4×1（題の長さで幅だけ変わる。高さは1マス ＝ 2行まで）／
  **焦点のタスク 4×2**（第132巡の 1.3倍をやめて、格子の1段上へ）。
- 格子の線は**アプリには出ない**（第132巡までの「罫線として見せない」）。
- 見本 … 第133巡に画像で提示（`grid-spec.png`。リポジトリには入れていない）。
