# Explore 刷新（確定版・2026-08-28）

いまの Explore を「提案」と「実行」の2本の柱に組み直す。
**生成の仕組み・データモデル・KEEP/SKIP の記録・今日を終える処理は一切変えない。**
変えるのは見せ方と操作だけ。

---

## 0. 言葉の方針（最優先）

- **画面に出る文字は一般語**。「提案 / ストック / マップ / プラン」。
- メタファー（鉄道・券・案内標）は**視覚だけ**で表現する。
  「本日の販売は終了しました」のような言い回しは使わない。
  空の状態は「今日の提案は以上です」程度の普通の文にする。
- 英字のラベル（`STOCK` / `VIA` / `TERM` など）はサインの語彙として使ってよい。

## 2. 券 ── 唯一の共通部品

1件＝1枚の券。場所によって**縮尺だけ**が変わる。

### ★組み方の正は **Vitsœ のラベル**（2026-08-28 にユーザー確定）

参照は3枚（AuBe のポスター／**Vitsœ のラベル**／Grilli Type の名刺）。
3枚に共通しているのは次の5つで、券はこれに従う。

1. 地は**紙か、ベタ1色**。券は**その色の紙そのもの**になる。
2. **文字は全部黒**。階層は色ではなく**大きさだけ**が作る。
3. **太い黒バー**か**極細の罫**で区画を割る。箱で囲わない。
4. **巨大な要素が1つだけ**。券では**題**（ユーザー確定）。
5. 色は幾何形か全面のどちらか。**文字には使わない**。

### 版面（幅 300 / 比 13:21 → 高さ 485）

```
　　　　　　　　　　　　　　　　　　  ← 全面がドメイン色の紙（紙の目を焼いてある）
  EXHIBITION              Nº 0143    nano caps ／ 通し番号
  ──────────────────────────────     罫（黒・1px）

  ┌────────────────────────────┐
  │           写真              │     ★周囲に余白をとった四角（裁ち落とさない）
  └────────────────────────────┘

  見えないものたちの庭                ★主役。display(26)/bold、最大2行
  音と光だけで構成された9つの部屋を…    body(13)、最大2行

        （余白は題の上下へ 3:5 で割る）

  ──────────────────────────────     罫
  会期      12.02 – 03.16            ラベル(和 micro ＋ 欧 nano) ／ 内容(body)
  SOON
  会場      東京都現代美術館・清澄白河
  VENUE
  ∘ ∘ ∘ ∘ ∘ ∘ ∘ ∘ ∘ ∘ ∘ ∘ ∘ ∘ ∘    ミシン目（穿孔）
  EXPLORE                 ▮▯▮▮▯     半券
```

- **段は3つだけ** … 題 `display`(26) ／ 内容 `body`(13) ／
  ラベル 和 `micro`(9)＋欧 `nano`(7)。比は 2.0 と 1.44 で design.md §5-2 を満たす。
- **余白は題の上下へ 3:5 で割る。** 片側だけに逃がすと、写真が無い券で
  中央がぽっかり空く（3巡目に実際にそうなった）。
- 期限が近いことは**色ではなくラベルの語**で伝える（`PERIOD` → `SOON`）。
  有彩色は紙の1色しか使わない。
- ★題と要約は `flexShrink: 0`。縮むと `-webkit-box` が**字の途中で切れる**。

### 紙の色 ── 黒が載る明るい4色

券は色紙になり黒い文字が載るので、**暗い色は使えない**
（forest / violet / wine の上では黒が沈む）。`SCHEME` の明るい4色を当てる。

| ドメイン | 色 |
|---|---|
| バショ `place` | sky `#509BF5` |
| タイケン `experience` | pink `#F76FA1` |
| ジョウホウ `info` | yellow `#F5E837` |
| モノ `thing` | orange `#FA6E31` |

### 紙のテクスチャは**下地**に

`public/paper-kraft.webp`（図形が焼き込んでいるのと同じ1枚）を
**色のすぐ上・文字の下**に `mix-blend-mode: multiply` で敷く。等倍・繰り返しなし
（★縮小しない。紙の目は高周波なので消える）。
★最前面に `overlay` で乗せると**写真も文字も霞む**（2巡目に実際にそうなった）。

### 鋏痕（入鋏の痕）

★**券の縁を切り欠く**形。大きさは**券の幅の 13%**。
★★券が彩度の高い紙になったので、切り欠きは**地との差だけで読む**。

**形の正は旧国鉄の鋏こん一覧**（46種・2026-08-28 にユーザー指定）。
一覧を見ると、鋏こんは例外なく「**券の縁が形の上辺**で、そこから下へ食い込む」
形で、輪郭は**直線と単純な弧が2〜4本だけ**。この規律から外れると鋏こんに見えない。

| ドメイン | 形 | 一覧の出典 | 輪郭の性格 |
|---|---|---|---|
| バショ `place` | **アーチ** | #4 大井町 / #6 蒲田 | 弧 |
| タイケン `experience` | **台形** | #26 藤沢 / #27 洋光台 | 斜め |
| ジョウホウ `info` | **角** | 予備2 / 鶴見 | 直角 |
| モノ `thing` | **二又** | 品川 / #22 恵比寿 | 切れ込み |

★4つは**輪郭の性格が全部違う**ものを選んである。小さく描いても混ざらないのは
このため。形だけ差し替えないこと。
★割り当ては**4ドメインで固定**（ユーザー確定）。一覧は駅ごとに46種あるが、
鋏痕は**マップのノードの形**と**ストックの絞り込み**でも同じ意味を持つので、
細かく分けるとその約束が壊れる。

**鋏痕は3か所で同じ意味を持つ**（文字を使わない分類）:
1. 券の縁の切り欠き 2. マップ上のノードの形 3. ストックの絞り込みアイコン

### 入鋏は垂直でなくてよい

`TicketPunch` は `edge`（4辺）・`t`（辺のどこか）・`tilt`（傾き・度）を持つ。
**切りたい辺を、好きな位置に、好きな傾きで**切り欠ける（ユーザー確定）。

★物理的に正しく描くための仕掛け … 鋏痕の形の**口から外側へ板（`NOTCH_LIP`）を
伸ばして**おき、その塊ごと**口の中点まわりに回す**。斜めに入れば口はそのぶん
広がり、券の縁は左右とも直線のまま残る＝実物の斜め入鋏。券の外へはみ出た分は
券の `overflow: hidden` が切る。
★板を伸ばさずに回すと、**縁に三角の紙のヒゲが残る**。

★陰は**口を除いた輪郭**（`notchContour`）にだけ落とす。閉じた輪郭を縁取ると
**券の縁そのものにも線が乗り**、切れ目ではなく「置かれた図形」に見える。

### ★★★パスの整理（22巡目・ユーザー指定）

> 現在の3Dモデルの形状（シルエット）は非常に良くできています。**これまで作成した
> Shape のパス（座標データ）は絶対に破棄しないでください。**… 現在は細かい座標点が
> 多すぎて線がガタつき、曲線が歪んでいる状態です。（2026-08-29・ユーザー）

なぞったパスは**シルエットは正しいが点が多すぎる**。直線が数本に割れ、カーブは
折れ線で近似され、長さ3の潰れた辺が各片に1本ずつ残っていた。
`tools/clean-nipper.mts` が、**シルエットを変えずに**次の順で整える。
数値は先頭の定数だけ（`TOL` 6／`MIN_EDGE` 5／`MERGE_DEG` 8／`MAX_TURN_DEG` 40／
`SNAP` 4／`FLAT_SAG` 2.5／`SLOT`）。

| # | 規則 | 何のため |
|---|---|---|
| 1 | 長さ 5 未満の辺を前の辺へ吸収 | 潰れた辺が面取りを壊す |
| 2 | 向きの差 8° 未満の直線を1本に | 直線が数本に割れている |
| 3 | 同じ向きに曲がり続ける直線3本以上を**円弧1本**に | ガタついたカーブ |
| 4 | 膨らみ 2.5 未満の弧を直線に戻す | 半径が大きいだけの偽のカーブ |
| 5 | 軸に近い辺を**完全に軸平行**にし、幅 4 のクラスタで座標を1つに揃える | 直線をまっすぐに |
| 6 | **スリットを軸平行の長方形に作り直す**（左 x=155／右 x=175／底 y=−229） | ユーザー指定 |

★★**急な折れ（40° 超）は「カーブ」ではなく角**。ここを見ないと、直角3つの
長方形（スリット）にまで円を当ててしまう（22巡目に実測 ― 溝のずれが 106 に出た）。
★★**スリットはいちばん最後に作る**。先に作ると、あとの規則が直角を丸めてしまう。
★★**スリットの範囲は生の `NIPPER_SLOT` の枠から取る**。「上のほうの点」で探すと
始点まで巻き込んで輪郭を切り落とす（22巡目に実測 ― ずれ 674・辺が 32→9 に落ちた）。
★点を動かしたら、**その点に触れる弧の中心を引き直す**（同じ半径・弦の同じ側）。
怠ると弧が端点から外れて隙間が出る。

### ★★★持ち手の内側を削る（23巡目・ユーザー指定）

| 画面の行 → モデルの y | 右 `行 = −1.325·y + 555` ／ 左 `行 = −1.370·y + 530` |
| 写像の確かめ（正面の面の幅） | 右 比較 641 件・残差 1.68px ／ 左 比較 714 件・残差 1.60px |
| 倍率（左右で**独立に**出した） | **1.340** と **1.344** px/単位 ―― 独立に一致したので写像は正しい |

削る量（モデル単位。`t`＝0 が頭との付け根、1 が内側のベベルの付け根）は
**右が最大15／左が最大9**と食い違った。これは**パースの見え方の差**なので
（右だけ側面が見えていて、実際は右のほうが細いのに画面では同じ太さに見える）、
ユーザー確定で**平均の12を左右に当てる**。鋏は画面内を動かす予定で、
`away` が変われば見え方も変わるから、**形そのものは左右そろえておく**のが正しい。

規則8（`tools/clean-nipper.mts`）:

```
削る量(t) = min( 12 · smoothstep(0, 0.7, t) ,  0.30 · (幅(y) − 面取り2つ) )
```

★★**上限（`cap`）が先端を守る。** 右の内側のベベルは横に 11 単位しか走っていない
ので、根元を 12 動かすと**ベベルが裏返る**。上限を入れると根元は 6.9（左は 10.9）に
収まり、ベベルは 4 単位ぶん残る。**実測でも先端では青い線が縁へ戻っていた**ので、
この緩みは計測とも合う ―― 理屈のある形で同じ結果になった。

★**削る場所は走って見つける**（辺の番号を書かない）。`topY` より下で、走査線ごとに
中心線に近いほうの縁に載っている**弧が連なったところ**。★★判定は**両端とも**内側で
あること ―― 終点だけ見ると、頭から降りてくる弧（左では段の境目の印を持つ辺）まで
巻き込む。★★**run の始点も動かす** ―― 始点は「1つ前の辺の終点」なので、そこを
直さないと弧が実際の始点を通らず**隙間が出る**（右の片は始点が根元なので必ず起きる）。

弧は**始点・中点・終点の3点**を動かして引き直すので、**辺の数は変わらない**。

結果 … 右・左とも弧3本、根元で 6.9／10.9 単位、いちばん削るところで 12 単位、
弧の引き直しのずれ 1.13／0.68、内側のベベルの残り 4.1／4.5、
最小のくびれ 51.0／53.3（面取り2倍 = 14）。

**右 比較 482 件・平均 −0.1 単位 ／ 左 比較 513 件・平均 +3.0 単位**
（左右そろえたぶんの差。狙いどおり）。

### 立体 ── 面取りと厚みを持たせる（`lib/nipperMesh.ts`）

`buildPart(多角形, 厚み)` は、平面図の多角形に**面取り**と**厚み**を与えて立体にする。
断面は z 方向に4つの輪:

```
   ─── 手前の蓋（内へ寄せた輪）      z = +t      ← 面取りの縁
  ╱
 │ ─── 本体（輪郭そのまま）          z = +t − c
 │
 │ ─── 本体                          z = −t + c
  ╲
   ─── 奥の蓋                        z = −t
```

- 面取りは**1段**（`CHAMFER` = 7）。角を落とした鍛造の塊に見せるのはこれ。
- 厚みは**片ごとに一定**（`HALF[tier]`）。どこがどの段かは塗り分けが持つ。
- 内へ寄せるのは**角の二等分線**に沿って。鋭い角では伸びが発散するので
  **3倍で頭打ち**にする（スリットの奥で自分と交差させないため）。
- ★★**巻きは反時計回りに揃えてから使う**。逆だと側壁の法線が内を向き、
  面が裏になって落ち、**中が透けて見える**（17巡目に実測）。
- 頂点は**共有しない**ので、法線は面ごとに立つ＝ローポリ。曲線は持たない。
- 針金（バネ）は8角形の断面の管。★**折れ線のまま**繋ぐ（`CatmullRomCurve3` を
  そのまま使うと曲線になる）。
  ★★**輪だけは滑らかにする** ― 1周を **48** で折る（18巡目。10 では
  「リングがリングに見えない」）。断面は8角形のまま。
  ★★★**輪は1本**（19巡目）。18巡目は2巻きを半径差3・z差4で重ねていたが、
  針金の直径 17 に対して差が小さすぎて融合し、**筒に見えた**。平面図も円を1本しか
  描いていない。半径と針金の太さは**図の実測**（`NIPPER_COIL.r` / `.wire`）―
  芯の半径は輪を放射に走査したインクの帯の中心、針金の太さは脚の2本線の**垂直**な
  間隔（斜めなので横に測ると太く出る／★対の**あいだ**が囲まれていることを確かめて
  数える。でないと道具の輪郭の縁を拾って倍になる）。
  ★★★**脚も図から測る**（20巡目。ユーザー指摘「リングの辺りの形が捉えられていない」）。
  脚は2本線で描かれていて、**そのあいだが閉じた領域として残っている**。輪の帯を
  除いてから、その領域ごとに**主成分**を取れば軸の両端が脚の端になる。
  ★領域は**地のものだけ**を採る ―― 部品に割り当てられた領域まで見ると、
  右の持ち手の内側の細部（1225px）を脚と取り違える（20巡目に実測）。
  ★輪は**脚が触れている角度から**1周する。付け根の角度も図が決めている。

### ★★彩色 ── 段は6色のまま（`MeshToonMaterial` を差し替える）

本物のなだらかな階調にはしない。**アプリの語彙を破らないため**、
`NIPPER_PAINT.ramp` の6色を `gradientMap` に食わせる。ただし three の既定は
2つの点で合わないので、`applyAppTones` が段の出し方を差し替える:

| three の既定 | 何が起きるか | 差し替え後 |
|---|---|---|
| `n·光` を 0 で切る | 光の裏がぜんぶ最暗の1段に潰れ、絵が平たくなる | `(n·光 + 0.45·n.y + 0.895) / 2.19` |
| 段の表の**赤だけ**を読む | 暖かい灰色が無彩色の灰になる | RGB をそのまま返す |

差し替え後の式は 16巡目までの `toneOf` と**まったく同じ**。
★光は**1つだけ**（環境光を足すと `gradientMap` を素通りして暗部が持ち上がる）。
★★`DirectionalLight` の強さは **π**。three は拡散を 1/π するので、
π を入れて 1 に戻すと、画面に出る色が段の表の色そのものになる。
★工具は**自分の影を受けない**（受けると影の中が真っ黒に落ちて、段が6つで収まらない）。
落ち影は床（`ShadowMaterial`）にだけ落とす。
