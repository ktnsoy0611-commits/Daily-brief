Daily-brief に **ホーム画面** を新設したい。仕様は **`docs/home-spec.md` が正**。
まず `docs/home-spec.md`・`design.md`・`handoff_current.md`・`CLAUDE.md` を読んでほしい。

**目的** … このアプリは時間管理でもタスク管理でもない。
**AI が先回りして「いま自分にとって最適なもの」を差し出す場**で、仕事も週末も余暇も同じ提案として扱う。
ホームはその玄関にあたり、3アプリの枠を越えて情報が一元化される画面。

**経緯** … 2026-09-05〜06 に16往復して設計を固めた（コードはまだ1行も書いていない）。
出発点は「上に候補のピルが並び、下に図形が積もる」1枚の絵で、
**ピルが形を変えて GRAVITY へ落ちる**のがデザインと機能の噛み合った点だと判断した。
そこから、置き場の規則・形の割り当て・印の規約・和文の組み方・配色が決まっている。
経緯と**却下した案（理由つき）**は `docs/redesign-ideas.md`、
参照の分析と**色の測定値**は `docs/redesign-references.md` にある。
★**却下済みの案を蒸し返さないこと。**

**あなたにやってほしいこと**

1. ★**まず質問してほしい。** `docs/home-spec.md` §12 に**未確定が6件**ある。
   それと、仕様を読んで**既存のコードと噛み合わないと感じた点**を、
   まとめて私に聞いてほしい。**合意できるまでコードを書き始めないこと。**
2. ★**分からないことは全部聞いてすり合わせること。推測で進めない。**
   仕様書に書いていないことに気づいたら、実装する前に質問する。
3. ★**既存のシステムと噛み合わないところは、勝手に決めずに議論すること。**
   既存の物理・タブ構成・色の対応表・データモデルに手を入れる必要が出たら、必ず相談してほしい。
4. 合意できたら `docs/home-spec.md` §10 の段取りで実装に入る。
5. ★**最高品質で実装すること。** 目標は Awwwards の「Site of the Day」級。
   そこへ届く道は汎用の UI キットで揃えることではなく、**自分の語彙をひとつも破らないこと**。

**寸法と位置について** … 仕様書には**構造・関係・意味**だけを書いてある。
具体的な余白・文字の大きさ・角丸・座標は**書いていない**ので、
**`design.md` と `lib/tokens.ts` の段から、あなたが決めてほしい**。
段に無い値が要るなら**目盛りの外**として、その行に `// ★目盛りの外（理由）` を書く。
