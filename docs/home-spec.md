## 0. これは何か

**ホーム** ―― 起動時に最初に出る画面。3つのアプリ（EXPLORE / TASK / JOURNAL）の**入口**であり、
3アプリの枠を越えて情報が一元化される場所。

**主題は時間管理ではない。** 「AI が先回りして、いま自分にとって最適なものを差し出す」場所。
仕事も週末も余暇も、同じ種類の提案として扱う。

## 1. 置き場の規則（★これ1本で全部決まる）

> **日付が無いものは帯（上）。日付が付いたものは山（下）。それだけ。**

- 提案・フォローアップ・声から拾った候補・いつかやる ―― **ぜんぶ「まだ日付が無い」で一致する**ので
  4種類ではなく1種類。置き場は帯ひとつ。
- 山にいるものは**全部「今日」**。だから山は説明が要らない。
- ★**日付を聞く正規の入口は「帯から下ろす手つき」1つだけ。** 編集画面でも変えられるが、
  入口を増やさない（増やすと「どこで決めたか」が散る）。

### 日付は2つある
| | 意味 |
|---|---|
| **帯の日付** | **見つけた日**（今日）。日付は中身ではなく**帯そのもの**が持つ |
| **山の日付** | **やる日**（今日） |

だから下ろす手つきは**2つの決断を同時にしている**（引き受ける ＋ いつ）。

## 2. 配色（★2026-09-06 ユーザー確定）

出どころ … 参照画像 `SKY / STORM / SEA / CREAM / ROSE` のパレット
（`tools/extract-palette.py` で画素から測定。**印字 HEX との差は最大 1**）。
そこへユーザー指定で**墨（黒寄りの soft black）**を1つ足す。

### 2-a. 値

```ts
// lib/constants.ts ―― PALETTE の6行をこれに差し替える
export const PALETTE = {
  sky:   "#C3BFE0",  // SKY   ── 藤
  storm: "#858AC2",  // STORM ── 青紫
  sea:   "#144474",  // SEA   ── 紺
  cream: "#FEE1D1",  // CREAM ── 生成りの桃
  rose:  "#E15442",  // ROSE  ── 珊瑚
} as const;

export const WHITE = "#FCF7F4";  // 地。★参照の中の白（純白ではない）
export const INK   = "#23252B";  // 墨。★黒寄りの soft black（純黒ではない）
```

**`INK` は既存の `#2C2627`（暖色）から `#23252B`（寒色）へ変える。**
パレットが寒色に寄ったので、暖色の墨だと墨だけが浮く。
より柔らかくしたい場合の代案は `#2A2C33`（白地との比 13.11。`#23252B` は 14.41）。

無彩色の段（`MUTED` / `SECOND` / `SURFACE` など）は **`WHITE` と `INK` の混色で導出する**。
表に書かない ―― 書くと墨を替えた人が片方だけ直す。

### 2-b. 実測のコントラスト比（`#23252B` 墨・`#FCF7F4` 地）

| 面 | 墨を載せる | 白を載せる | 面として地の上 |
|---|---|---|---|
| WHITE `#FCF7F4` | **14.41** | — | — |
| CREAM `#FEE1D1` | **12.33** | — | 1.17 |
| SEA `#144474` | 1.54 | **9.37** | 9.37 |
| STORM `#858AC2` | **4.68** | 3.08 | 3.08 |
| SKY `#C3BFE0` | **8.64** | 1.67 | 1.67 |
| ROSE `#E15442` | **4.05** | 3.56 | 3.56 |

★★★**ROSE だけが AA（4.5）に届かない（4.05）。**
ROSE の面に載せる和文は **`TYPE.lead`(16) ／ `WEIGHT` 700 以上**とし、
その行に `// ★目盛りの外（ROSE の比 4.05。面としての役が要るため）` を書く（`design.md` §6）。
**ROSE に `TYPE.body`(13) 以下を載せない。**

### 2-c. 色を出してよい場所（★これ以外は白と墨だけ）

| 出る | 出ない |
|---|---|
| 帯の**上段**（提案のカプセル・急ぎのカプセル） | 帯の中段・下段 |
| 山の**提案の丸** | 山の**タスクの四角** |
| 山の**未読のバッジ** | タブバー |
| 写真のデュオトーン | 持ち物のアイコン |

★これで**骨格が色から独立する**（配色を替えても構造が動かない）。

### 2-d. 役 → 色

| 役 | 色 |
|---|---|
| 急ぎ（フォローアップ） | **ROSE** |
| 提案 ── 1枚目 | **STORM** |
| 提案 ── 2枚目以降 | **SKY** → **SEA** の順に循環 |
| 未読のバッジ | **ROSE** |
| 2つ目の明るい面（中段のピル・タスクの一部） | **CREAM** |
| 大きな英語（SUNDAY） | `mix(WHITE, INK, 0.13)` ＝ 地より少し濃い灰 |

## 3. 画面の構造（★上から下への並びだけ。寸法と位置は `design.md` に従って決める）

1. **小さな見出し** … `HOME ／ 06 SEP ／ SUN`。★**大きな英語はここに置かない**（§8）
2. **持ち物のアイコン ＋ 数字のバッジ**（画面の右上に固定）
3. **帯 3段**（§4）── 互い違いに逆方向へ流れ、**左右とも画面の外へ切れる**
4. **山（GRAVITY）**（§5）── 大きな英語（SUNDAY）／未読のバッジ／タスクの四角／提案の丸
5. **タブバー** … `EXPLORE ／ TASK ／ JOURNAL` ＋ 右端に作るの丸

**左右のパディングはページ最上位の器だけが持つ**（`design.md`）。
★**帯だけは例外で、器のパディングの外へはみ出す** ―― はみ出しが「まだ続きがある」を言うため。
その行に `// ★目盛りの外（帯は器の外へ出る。続きがあることを形で言う）` を書く。

## 4. 帯（上）

### 4-a. 段 ＝ 出どころ
| 段 | 中身 | 見た目 |
|---|---|---|
| **1** | AI から来たもの（提案・フォローアップ） | **太いカプセル h70**。★**写真を持つのは提案だけ**。急ぎは ROSE の面（写真なし） |
| **2** | 自分の声から出たタスク候補 | **CREAM のピル h52** |
| **3** | いつかやる（期限なし） | **縁だけのピル h46**。塗られていない＝時間を割り当てていない |

★**上の段ほど厚く・濃く・速い。** 3つの規則が同じ向きなので説明が要らない。

### 4-b. 大小の関係（★具体的な値は `design.md` の段から引く）

- ★**上の段ほど厚く、濃く、速い。** 3つの規則が同じ向きを向いているので説明が要らない。
- 段1のカプセルは**段2・3のピルより明確に厚い**（第26便で「もっと大きく強調」と指定）。
- 段1の写真の丸は**カプセルの高さいっぱい**、`border-radius:50%`、左端に密着。
- 文字は段1 > 段2 = 段3。**すべて `TYPE` の段から選ぶ**（`lead`(16) / `body`(13)）。
- 段3の縁は 1.5px、色は `mix(WHITE, INK, .30)`。

### 4-c. 動き（★確定）
- **自動でゆっくり流れ続けて循環する。**
- **段ごとに向きが互い違い** … 段1 = 左へ ／ 段2 = **右へ** ／ 段3 = 左へ。
- 一周 … 段1 **44秒** ／ 段2 **58秒** ／ 段3 **72秒**（＝**いつかやるほど遅い**）。
- **左右とも画面の外へ切れる**（＝まだ続きがある、を形で言う）。
- 実装 … 中身を**2回並べて** `translateX(-50%)` を線形で無限に。逆向きは `animation-direction: reverse`。
- **指で触れている間は止まる。離すと流れ出す。**
- `prefers-reduced-motion: reduce` で停止。
- ★代償 … 動くものは目を引き続けるので、速度は**1秒に 8px 前後**（読めるが追わなくていい）まで
  落としてある。実機で速ければ**さらに半分**まで落とせる。

### 4-d. 操作
- **タップ** … 詳細へ（編集できる）。
- **掴んで下へ** … 日付を割り当てて山へ落とす（§6。**実装済み**）。
  ★**右端へ寄せれば ASSIGN の帯**が出て、離すとカレンダー（§6-d）。
- ★**ピルに印（アイコン）を付けない。** 列に印が並ぶと**印が「模様」になって印でなくなる**。

## 5. 山（下 ／ GRAVITY）

### 5-a. 山は何か（★確定）
> **上の帯 ＝ まだ自分の時間を割り当てていないもの**
> **下の山 ＝ 自分の時間を使うと決めたもの**

展覧会も**入る**（行くと決めた時点で「自分の時間の使い道」だから）。
**違いは分類ではなく形が言う。種類でレーンを分けない。**

### 5-b. 形 ＝ ジャンルの札（★意味づけはしない）
| 形 | 中身 | 備考 |
|---|---|---|
| **ピルの積み**（段の数＝題の文字数・最大3段） | タスク | **文字が組める唯一の形**。★**1件が1つ**（まとめない）。★★第99巡に「辺の数＝埋まり具合」から替えた。`lib/solid.ts` の `stackOutline` |
| **札の形**（4つ。四つ葉／六角形／波打つ四角／トゲトゲ） | 提案（今日行くと決めたもの） | ★**写真を入れられるのはこれだけ**。形は**ジャンル**が決める（`lib/cardShape.ts`。BRIEF の札と同じ1か所） |
| **ギザギザの円**（12頂点・内半径 0.40） | 未読の提案の枚数 | **1画面に1つだけ**。0 になると消える |
| **カセット**（青い本体＋墨のリール2つ＋黒い下の段） | まだ声を録っていない日 | ★★★**JOURNAL のタブのアイコンそのまま**（第94巡に円から替えた）。**文字は載せない**。寸法は `lib/cassette.ts`・リールの芯は `lib/reelHub.ts` ＝ `VoiceStudio` と同じ部品 |
| **大きな英語** | 今日の日付と曜日 | ★**2枚の板として山と一緒に落ちる**（2026-09-07 ユーザー指定で「版面の柱」から変更）。作りは `lib/wordPlate.ts` ＝ GRAVITY と同じ部品 |

★★★**塗り分けは「日付があるか／ないか」の1軸だけ**（2026-09-12・第93巡）。
**日付あり＝メインカラーの塗り／日付なし＝輪郭線**（中は地と同じ色、縁と字は
メインカラー）。**帯のピルと図形で同じ言い方**にしてあるので、帯から掴んで
日付を割り当てた瞬間に塗りへ変わる。★タグは廃止した。

★**形に物語を持たせない。** 持たせた瞬間に当てはまらないものが出る
（「返事待ち」は義務か誘いかで詰まった）。★**ジャンルが増えたら色で分ける。形は増やさない。**
半円・八角・16角・アーチ・封筒・時計は**すべて却下済み**。

### 5-c. 積み方
- **大きさ ＝ 重要度**（文字数ではない。ユーザーが決めた重要度）。
- **傾きは 3〜6° だけ**。★**0° だと格子になって「積もった」に見えず、10° を超えると漫画になる。**
- 図形の中の文字は**左上に寄せる**。★**中央揃えにした瞬間にバッジ・シールになる**（`design.md` の版面の規則）。
- 物理は既存の matter.js（`components/tabs/GravityTab.tsx`）を使う。
- ★★★**器は GRAVITY とまったく同じ箱**（2026-09-11・第92巡）。左右は
  `lib/pileBox.ts` の `PILE_INSET`（＝タブバーと同じ 16px）、床は
  `floorYOf(h) = h − navHeightPx() − GROUND_LIFT`。
  ★★**この式は「器が画面の底まで伸びている」前提**なので、山の器には
  **`.bleed-x-b`**（左右 ＋ 下のタブバーぶん）を付ける ―― タブの器は
  `paddingBottom: var(--nav-h)` を持つので、付けないと**タブバーの高さが二重に
  引かれて**床が浮く（実測 … 実機で 164px。狙いは 32px）。
  ★**式に旗を足して逃げないこと。器を揃えるのが正。**
- ★★★**器が変わったときの約束は3つ**（2026-09-14・第103巡。ユーザー報告
  「図形が地面の下に落ちる」「横画面にして戻すと図形が消える」の根治）…
  1. **床が動いたら壁を作り直す。** 床は `navHeightPx()` に依存するので、
     **器の寸法が変わらなくても動く**（`env(safe-area-inset-bottom)` が
     遅れて 0→34 になる）。`ResizeObserver` だけでは足りない。
  2. **床が上がったぶんだけ山ごと動かす**（`refitPile`）。床の板は 200px と厚く、
     板の中に入った図形は**いちばん浅い軸＝下へ**押し出されて抜ける。
  3. **器が大きく変わったら大きさを決め直し、外へ出た図形は拾い直す**
     （`isLost` → `respawn`）。器には天井も底も無いので、一度外へ出た図形は
     **二度と戻らない**。★山が空にならない限り入れ直しの番人も撃たない。
  4. ★★★**沈んだだけなら「その場で床へ戻す」**（`sink`。第104巡）。
     **上から落とし直さない** ―― 沈む原因が残っているかぎり
     「沈む → 降る → また沈む」を繰り返し、**雨のように見える**。
  5. ★★★**物理の歩数は実時間から決める**（第104巡）。`requestAnimationFrame` ごとに
     1歩だと、**120Hz の実機で物理が2倍速**になって図形が床を突き抜ける。
  6. ★★★**重さの目盛りは1つ**（第104巡）。**`setMass` を呼び忘れた体だけが
     matter の既定の密度（px²）になり、他の全部（solid²）と桁が違う。**

## 6. 下ろす手つき ── 日付の割り当て（★★★2026-09-14・第102巡に確定・実装済み）

★★★**K1「一週間が地面から7本の柱になる」はやめた**（ユーザー確定）。
柱は**遠い日が選べない**のが致命で、しかもカレンダーの盤は
`components/tasks/WhenSheet.tsx` に**すでに戦い抜いた実物がある**。
**柱を作るより、その盤を持ち上げて使い回すほうが正しい。**
★K2（点の集まり）・K3（下から暗いシート）も**採らない**。**この節が正。**

### 6-a. ユーザーの説明（★これがそのまま仕様）

> ピルを触ると**少し柔らかいような感触**がして、少し下に引っ張ると最初は**少しゴムの
> ような反発**する感触がして、そのまま引っ張っていくと**ピルの形から、ホームに落ちて
> くる時の図形の形に変化しながら滑らかにアニメーションして指に吸い付いて**くる。
> そのまま**ホームのところで指を離すと、日付が今日になってシステム的にも今日に
> 割り当てられたことになって、そのままホームに落とされます**。
> **別の日付を割り当てる場合**は、掴んだまま**画面の右端に近づけると右端から黒い帯が
> 出てきて、「ASSIGN」と書いてあります**（帯の出方もベジエ曲線でスムーズに）。
> そこで**離すとカレンダーの画面**が出てきて、上部に**今日・明日・来週**のボタン、
> カレンダーは**横にスワイプ**でき、**割り当てたい日付をタップすると登録が完了**。
> また**ホームの図形も長押しで掴んで自由に移動**させられるようにして、**同じ操作**
> （右端に近づけたときの動き）が行えるように。

### 6-b. 状態機械（★一本道。分岐は「離す先」だけ）

| 段 | 何が起きるか | 出どころ |
|---|---|---|
| 触る | ピルが**わずかに沈む**（`scale(0.97)`） | `--t-press` / `--ease-press`（**押下だけ非対称**） |
| 1px でも下へ | ★★★**そこから先は canvas の写し取り**（DOM のピルは消える。ただのタップでは切り替えない） | `pillGhost.drawPillGhost()` |
| 少し下へ（**〜44px**） | ★★★**両端は帯に残り、掴んだ一点だけがゴムのように垂れる**（＝**輪ゴムを引っ張る**）。★★**垂れは指と 1:1**（第107巡。実測 … 指を 6px 下げるごとに +5.5〜6.0px）。上限 **70.4px** | `bendAt()` / `PULL_RESIST`(1.0) / `BEND_TOP`(0.55) |
| **44px**（＝ピル1つぶん）を越える | ★★★**ばちん** … ピルが図形になり、**指へ「一気に、でも滑らかに」追いつく**（★瞬間移動しない。実測 … 28px を **4フレームで届き、10.5% 行き過ぎてから戻る**）＋`haptic(12)` | `K_CATCH`/`D_CATCH` ＋ `SNAP_POP` |
| **弾けてから 450ms** | ★★★**ばね一発** … くびれが**一息に開き、8% 行き過ぎてから収まる**（実測 … 150ms で開き、224ms が山、450ms で完全に静止）。**段は1つずつ生えない**（第107巡にユーザー確定「**ぽこぽこは気持ちよくない**」） | `K_CATCH`/`D_CATCH` ＋ `Ghost.waist` |
| 引いている間ずっと | **指の下にぶら下がって揺れる**（指が右へ動けば図形は左へ残り、止めると揺り返してから静かに戻る） | `K_SWING`/`D_SWING`（`lib/spring.ts`） |
| 同上 | **引く速さで伸び、止めると一度潰れて戻る**。★**面積は保つ**（`sx·sy = 1`）ので大きさは変わって見えない | 同上 |
| 右の縁から 72px | 右端から **ASSIGN の帯**が滑り込む | `--t-in` / `--ease-sheet` |
| ホームで離す | **今日**が入って**そのまま山へ落ちる** | `dueDate` / `plannedFor` に今日 |
| 帯の上で離す | **カレンダーの画面**（`AssignSheet`） | ― |
| 途中で離す | **何も起きない**（帯へ戻る。ユーザー確定） | ― |

★★★**進みは「時間」ではなく「指が引いた距離」で決まる。** だから曲線4本
（`lib/motion.ts`）を使わない ―― あれは**時間**の語彙。ここは物理と同じ
**目盛りの外**（`design.md` §6）。摘みは …
`PULL_ARM`(**44** ＝ `BAND_H.plain`) / `PULL_RESIST`(**1.0**) / `PULL_GIVE`(1.6) /
`BEND_TOP`(0.55)。
★★★**弾けたあとは「ばね1本」**（`K_CATCH`/`D_CATCH`）。
★★★**削除して復活させないもの** … `MORPH_SPAN`(距離・第105巡) ／
`MORPH_STEPS`(線形の時計・第106巡) ／ `shownRows`(段の階段) ／ `STEP_POP` ／
**`SNAP_POP` と `pop`**（★バネを2本掛けると**面積が 1.2秒 揺れ続けた**。
**一発 ＝ ばね1本**）。
★垂れの上限 **28.8px** は `PULL_ARM × PULL_GIVE × PULL_RESIST` から**式で出る**
（生の上限を別に置かない）。
★★★**第103巡の 56px・42% は「最初の抵抗が強すぎる」と差し戻された**（第104巡）。
**引き始めが死んでいると、そのあと何をしても取り返せない。**

### 6-c2. ★★★帯のピルの写し取り（2026-09-14・第105巡にユーザー確定）

**触った瞬間（下へ 1px）に、帯のピルとまったく同じ見た目を canvas へ写し取る。**
理由は1つ ―― **`.band-row` は `overflow: hidden`** なので、DOM のままでは
**帯の外へ垂れられない**。以後その絵が**曲がり → 弾け → 図形になり → 山へ落ちる**まで、
**手つきが一本の続きになる**。

★★**寸法は `Band` が実測した矩形**（`PillLook`）。書体・余白・色は DOM と同じ
トークンを読むので、**数を二重に持たない**。
★★★**踏んだ罠は3つ**（どれも画素で突き合わせて見つけた）…
① **掴んだ瞬間の矩形では 1.2px ずれる**（帯が止まるのは段の `onPointerDown` ――
ピルのあとに走る）→ **写し取る瞬間に測り直す。**
② **`border` は余白の外側に積む**（輪郭だけのピルは中身が `PILL_EDGE` ぶん内へ寄る）。
③ **`offsetWidth` は整数へ丸まる**（0.02px 足りないだけで題が1文字切り詰められた）
→ **矩形 ÷ 実測の押下の倍率**で割り戻す。
★写真は**帯の `<img>` そのもの**を渡す（URL で取り直すと、写し取った瞬間はまだ届かない）。
★★**引いているあいだは山の canvas を帯の上へ**（`HomeTab` の `zIndex`）。

★実測（WebKit 390×844・dpr 2。1px 引いた前後）… **中身（縁の内側）の違いは
提案 1.43%（平均差 0.99）／タスク 0.43%（平均差 0.23）**。
**違うのは縁だけで、それは狙いどおりの垂れ**（1px の時点で 0.75px）。

## 12-c. ピル → 図形の変形（★★★**死文**。第102巡に実装した中身は §6-c）

★★★**下の「48点の `clip-path` を補間する」案は採らなかった。** canvas に描いて

**帯のピル（角丸 999）から、山の図形（角丸 12 の四角／円）へ、連続的に変形する。**
