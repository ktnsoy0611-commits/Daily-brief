## 確定（ユーザーが明示的に決めたことだけ）

### 目的
- このアプリは**時間管理でもタスク管理でもない**。
  **AI が先読みして「いまの自分に最適な提案」を出す場**である。
  仕事（タスク）も、週末どこへ行くかも、余暇の使い方も、**同じ1つの提案**として扱う。
- アプリが自分を理解している、と感じられること。具体的には次の4つ（2026-09-05）:
  - (a) 今日やるべきことが正しい順で並んでいる
  - (b) 週末の前に、行きたくなる提案が届く
  - (d) 自分が忘れていたことを思い出させる
  - (e) 「先週こうだったから今週はこう」と流れを踏まえている
- ★**(c) 気分の察知は要らない**（2026-09-05 に除外）。

### 構造
- **ホームを設ける。** 位置は **「起動時に必ず出る玄関」**。そこから3アプリへ降りる
  （アプリの並びはホームより下の階層になる）。
- ホームには、AI が精査した**見るべき情報だけが優先順位づけされて**出る。
  **AI の判断の根拠は見せなくてよい。**

### 使い方
- 開く場面は **朝の出勤 / 1日の終わり / 暇なとき / タスクを追加したいとき**。

### 規約の解禁（2026-09-05）
- **形の規約を更新してよい**（角丸 22/999/50% の3つだけ、という縛りを外す）。
- **書体の規約を更新してよい**（Archivo + Noto Sans JP の2つだけ、という縛りを外す）。
- **グラデーションを使ってよい**（べた塗り限定を外す）。

### 検討の前提から外すもの
- **券（チケット）** … 第69〜81巡の Explore 刷新の中心。**保留**。
- **改札鋏（`Nipper`・three.js）** … 券とセット。**保留**。
- **ゴールのバインダー** … **保留**。
- ★保留＝**検討の入力から外す**。コードは消さない（`DEV` タブごと最後に処分）。
- **テープ（声の記録）** … 図形として統一できそう、という見立て。継続検討。

### 進め方
- **一度で全パターンは出せない前提で、段階に分けて出す。**
  少数案で勝手に先へ進めない。
- 提案は**絵と一緒に、数個ずつ**。まず全体で何案ありうるかの地図を出し、順に精査する。
- 参照画像は**ムードの寄せ集め**であって、統一されたテイストではない。
  **こじつけない。客観的に軸だけを抜く。**

## 参照サイトの分解（2026-09-05・第2便）

`https://links.taiyo-p.co.jp`（大洋LINKS）と `https://labs.google`（Google Labs）。
見た目は正反対（ビビッドな和文／無彩の欧文）だが、**やっていることは同じ** ――
**色面が1つのものを表し、その「形」が何であるかを語る**。抜いた部品は8つ。

**大洋LINKS から**
1. **タブのある面（フォルダ）** … セクションが書類フォルダの形で積まれ、
   **重なりの深さがそのまま階層**になる。
2. **英語の小見出し ＋ 和文の大見出しの対** … 全ブロックが必ず持つ。
   **英語＝分類、日本語＝中身**。役割が固定。
3. **花形の動作ボタン** … 「進む」は必ずこの一つの形。**形が動作の署名**。
4. **べた1色の全面 ＋ 巨大な和文** … 読む前に、色で何の画面か言い切る。

**Google Labs から**
5. **形の語彙（マスク）** … ものごとに輪郭が違う。**色ではなく形が識別子**。
   並ぶと別物だと分かり、しかも同じ一族に見える。
6. **色の器 ＋ 中の白抜き** … 外の色面が分類、内の抜きが中身（写真）。
   **写真が何であっても秩序が保たれる。**
7. **1本の線の上に立つ** … 形の違う図形が同じ床に並ぶだけで「これで全部」になる。
8. **ピル** … 両サイト共通。押せるものと絞り込みは例外なくピル。

### ★取り込むと壊れるもの（未決。決めないと先へ進めない）

## 第3便（2026-09-05）── 部品を軸に据えた。★参照は `docs/redesign-references.md`

★ユーザー指定「**部品はかなり欲しいものに近い。これを軸に活かす**」。
足りなかったのは2つ ―― ①**写真をデザインに取り込むこと** ②**部品の組み合わせ方**。
★★**ひとつのモジュールで全部を整理しきることはできない**（タスク・提案・AI の先回り・

### 情報の性質 → 部品（提案。未承認）
| 情報 | 部品 |
|---|---|
| AI の先回り（今日の一件） | **開いたフォルダ**。写真・理由・動作のピル。1日1件だけ |
| 提案（場所・体験・モノ） | **形マスクの写真**。形＝ドメイン |
| タスク | **ベタ塗りの図形**。棚か山にまとまり、量が読める |
| 予定（時刻がある） | **ピル**。数字が主役なので図形にしない |
| 持ち物・下準備 | **小さな円の列**。読めなくてよい。数と埋まり具合だけ |
| 記録・声 | **点の列（波）**。大きさ＝長さ。そのままログになる |

### 部品を束ねる6条（提案。未承認）
1. **図形は6つで打ち止め**（円・角丸四角・六角・クローバー・花・波）
2. **色は「種類」しか言わない**（強さ・優先は大きさと位置で言う）
3. **写真は抜いて2色に写す**（形マスク＋デュオトーン。生のフルカラーを置かない）
4. **押せるのはピルと花だけ**（ピル＝その場で決まる／花＝下の階へ開く）
5. **色が主役の面は1画面に1つ**（Heap の作法。騒がしい面と静かな面を交互に）
6. **英語＝分類、日本語＝中身**（大洋の作法。既存の `Masthead` と同じ）

★★★**Heap から採ったのがいちばん大きい** ―― **ひとつの図形だけで、装飾も図解も
グラフも入力欄も全部やる。語彙を増やさないことが統一感の正体だった。**

### 写真の扱い（提案。未承認）
5通りを比べた（素／形で抜く／デュオトーン墨／形＋デュオトーン色／色面の中の窓）。
**基本は「形で抜く ＋ ドメインの色のデュオトーン」、控えが「墨のデュオトーン」。**
理由 ―― ①彩度を落として2色へ写すので**パレットの色数が増えない** ②明るさの範囲を
自分で決められるので**上に載せる文字のコントラストが写真によらず保証できる**
③混色（`multiply`/`lighten`）では同じことができない（切り捨て・非線形。第81巡に実測）。
★**券の実装（`components/explore/samples` のデュオトーン）がそのまま効く資産**。

### ホーム3案 ── 違いは「写真と図形の出会い方」だけ
- **案1 重ねる** … 写真は最前面の1枚の中だけ。下はフォルダの背とタスクの棚。上から下へ減衰。
- **案2 分ける** … 1本の線で上＝AI から／下＝自分の。上は写真、下は図形。
- **案3 溶かす** … デュオトーンで色域を揃え、**写真と図形を同じ山に混ぜる**。

## 第5便（2026-09-06）── 「静かにする」は誤読だった。**構造は定数、色と形は変数**

### ★★★撤回した2条（第4便の 5・6）
- ❌ **有彩色は2つまで** … 根拠が無い。**Google Labs は1画面に6色以上、大洋も
  青・緑・黄・桃が次々に来る**。色はドメインとタグの数だけ使ってよい。
- ❌ **変なものは1つだけ** … 逆だった。**Labs のカードは全部が色ベタで、全部が
  変な形のマスクを持つ**。静かな要素は1つも無い。

### ★★★正しい原理（2サイトを数え直して分かったこと）
**まとまりは「静かさ」ではなく「構造の同一性」から来る。**
- Labs の単位 … 〈色ベタの器 → 白い変形マスクの画像 → 題 → 説明 → ピル〉。
  **この順番と余白は全カードで同一**。振れているのは**色とマスクの形と画像**だけ。
- 大洋の単位 … 〈英語ラベル → 和文の題 → 花形ボタン〉。**毎回同じ**。変わるのは**色**。
- ★**形が違っても一族に見えるのは、大きさと置き場が揃っているから。**
  **形の種類を減らす必要はない。**

### ★維持する基本
- **段の外の数字を書かない**（`TYPE` / `SPACE` から引く）。ただし**段の「数」は制限しない**。
- 左右のマージンは1本。

### ★★ホームは1画面に収めない（ユーザー指定・2026-09-06）
**縦にスクロールして出てくる**、または**画面が切り替わる**、どちらでもよい。
★**洗練＝色を減らすことでも、全部をグリッドに従わせることでもない。**

## 第6便（2026-09-06）── ★★★骨格（シークエンス）の分析

★ユーザー指摘 … 見てほしかったのは**部品ではなくページ全体の構成**。
どういう順番で節が並び、下へ行くと何が起きるか。
★★私が抜かしていたのは**シークエンス（順番と縮尺の変化）**。毎回「1画面にどう並べるか」
だけを考えていたので、縦に伸ばしてもベントグリッドにしかならなかった。

### 実際の節の並び（サイトから取得）
**大洋LINKS** … 9節。**同じ形の章を6回くり返す。**
HERO（情報ゼロ）→ ABOUT US → BUSINESS → FEATURE → OUR SHARES → TOURS →
RECRUITMENT →（ループする画像の帯）→（音の出る猫）→ FOOTER。
★**どの章も構造が完全に同一**（英語ラベル → 和文の見出し → **代表4枚** → 詳細へ）。
★**変わるのは色と中身だけ。** 節ごとに地の色が変わる＝章の栞。

**Google Labs** … 9節。**同じカードが縮尺を変えて3回出る。**
HERO（主役4件・横カルーセル・大）→ Be the first（5件・中）→
Grid + Filter（12件超・小。All/Create/Develop/Explore/Learn）→ About（散文。カード0）→
Beyond the Lab（卒業5件。**時間の軸はここだけ**）→ Community → FOOTER。

### ★★★骨格の文法6条（2サイトに共通。未承認）
1. **最初は情報ゼロか、主役ひとつ。** 一覧から始めるページは片方も無い。
2. **同じ単位が縮尺を変えて何度も出る。** 新しい部品を足さず、**同じ部品を縮める**。
3. **章の切れ目は「色」か「絞り込み」。** どちらも罫線を引いていない。
4. **各章は「代表4件 ＋ 続きへ」。** 深さは**別ページ**（大洋）か**フィルタ**（Labs）へ逃がす。
5. **時間の軸は最後に一度だけ。** 過去は終盤に置き、本編に混ぜない。
6. **最後は本題から外れたもので終わる。** 読み終えたあとに力を抜く節がある。

### ホームの骨格3案（見た目はまだ描かない。未承認）
- **A 漏斗**（Labs の骨）… TODAY 1件 → FOR YOU 3件 → MINE 全部（絞り込み）→
  LAST WEEK（過去・点の列）→ 今日を終える。
  効く＝朝に迷わない／危ない＝主役が外れると一日残る。
- **B 章立て**（大洋の骨）… 宣言（情報ゼロ）→ TODAY / WEEKEND / MINE / RECORD の
  **同一構造の章を4つ**（各代表4件・続きは各アプリへ）→ 願いが漂う帯。
  効く＝**ホームが目次として働く**／危ない＝**均等すぎて優先順位が付かない**。
- **C 浅いホーム**… TODAY 1件 → **件数だけの節**（中身を見せない）→ 今日を終える。
  深さは**画面ごと切り替えて別の場**へ。
  効く＝**絶対に散らからない**／危ない＝全体を掴む用途に応えない。
