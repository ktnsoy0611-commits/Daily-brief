## 1. 提案をどう置くか ── P1〜P12

**どれも「山と同じ画面に居るが、タスクとは別物だと形か物理で分かる」ことが条件。**

| | 名前 | 仕組み |
|---|---|---|
| **P1** | **浮く（浮力）** | 提案は**上へ浮く**。タスクは下へ落ちる。**同じ物理エンジンで重力の符号が逆**。画面の上半分に自然に溜まり、下半分がタスクの山になる。**混ざりようがない。** |
| **P2** | **吊るされる** | 天井から紐で吊り下がって静止している。**紐を切ると落ちてタスクになる。** 採用の操作が物理そのもの。 |
| **P3** | **地面になる** | 画面のいちばん下に提案が横一列に敷かれ、その上にタスクの山が積もる。**提案＝土台、タスク＝荷物。** タスクが減ると提案が見えてくる。 |
| **P4** | **奥の層にいる** | 提案は山の**奥**にあってぼやけている。二本指で押し広げるとピントが移り、提案が手前・タスクが奥になる。 |
| **P5** | **壁に貼り付く** | 画面の左右の縁に貼り付いていて、山とは接触しない。指で剥がすと落ちる。 |
| **P6** | **穴として在る** | 山の中に**色が抜けた穴**があり、覗くと写真が見える。**物ではなく場所**として存在する。 |
| **P7** | **背景の1枚** | 山の背後に全面の写真（デュオトーン）が1枚敷かれ、図形の隙間から見える。**今日の提案＝今日の地の風景。** |
| **P8** | **封をされている** | 閉じた封筒の形で山に混ざる。中身は見えない。タップで開く。**開くまでタスクと同格に扱われない。** |
| **P9** | **片付けると降ってくる** | 山が空に近づくと提案が上から降ってくる。**片付けた分だけ遊びが増える。** |
| **P10** | **隣の面（横スワイプ）** | GRAVITY の隣が提案の場。同じ物理だが**そこは「まだ自分のものではない」場所**。持ち帰るとこちらへ落ちる。 |
| **P11** | **振ると浮き上がる** | 画面を払う／端末を振ると、山の隙間から提案が浮き上がる。**普段は隠れている。** |
| **P12** | **額縁の図形（第8便A）** | 輪郭を内側へオフセットした額縁の窓に写真。**円と半円だけ**。※これ単体では足りないと判明済み。P1〜P11 との**組み合わせ材料**として残す。 |

★**私の見立て（未承認）** … **P1（浮力）** がいちばん強い。物理エンジンを1つしか使わず、
**「上＝外から来たもの／下＝自分のもの」が体で分かる**。P2・P3 が次点。

## 4. 案1〜3 の作り直し ── R1〜R6

★「まとまっているようで統一していない／ユニークさが足りない」を埋める別案。
**却下ではなく作り直し。** カードもグリッドも使ってよい。

| | 元 | 足す「ユニークさ」 |
|---|---|---|
| **R1** | 案1 カルーセル | **カードが横に流れるのではなく、山から1枚ずつ「引き抜かれて」手前に来る。** 送るたびに前のカードが図形に戻って山へ落ちる。カルーセルの左右送りが**物理の出し入れ**になる |
| **R2** | 案1 カルーセル | **カードが積み重なった束**（第2便の参照 Events アプリ）。上の1枚をめくると下から次。めくった1枚は**ピルに変形して上の帯へ入る**（＝あとで） |
| **R3** | 案2 上から引き下ろす | **引き下ろす量で世界が連続的に入れ替わる。** 0%＝カードのホーム、50%＝カードが図形に変形しかけ、100%＝完全な山。**M2 の連続変形をそのまま画面全体に当てる** |
| **R4** | 案2 上から引き下ろす | 引き下ろすと**カードが天井から吊り下がったまま降りてくる**（P2 と接続）。手を離すと戻る。切ると落ちる |
| **R5** | 案3 重力が一番上 | 境界が固定ではなく、**スクロール位置で山の重力が弱まる**。下へ行くほど図形が浮いて整列し、**グリッドに変わる**。スクロールが「重力の強さ」のつまみ |
| **R6** | 案3 重力が一番上 | 下の整然の世界を**グリッドではなく「棚」**に。山から落ちたものが下の段に**受け止められて整列する**。上が乱れ、下が整うのが1つの連続した動きになる |

★**R3 と R5 は「M2 連続変形」を画面全体に拡張したもの**。この2つは M1・M2 が決まってから見るのが早い。

## ★★★第17便（2026-09-06）── 「詰め込み」と「構図」は違う

★ユーザー指摘 …「**デザイン的にちゃんと考えられて作られたものではなく、
ただただ必要なものを全て詰め込んだだけにしか見えない**」。

★★★**私の失敗の構造** ―― 載せるべき内容を並べて、置き場所を変えた案を出していた。
**それは組み立てであって、構図ではない。**
出発点の画面が良かったのは内容が少ないからではなく、
**主役が1つに決まっていて、他が全部それに従属していたから**。

### ★以後の作り方（この順でしかやらない）
1. **先に構図を決める**（主役は何か／従属は何か／視線はどう流れるか）
2. **その構図に入らないものを外す**。**外したものを明記する**
3. 外したものの行き先は**構図が決まってから**考える（先に決めるとまた詰め込みになる）
4. ★**1案につき1つの構図**。**内容の置き場を変えただけの変種は出さない**

## 第18便 — 山は何か（2026-09-06）
Artifact: https://claude.ai/code/artifact/377f070d-9690-4c50-9d49-b37088e164e7

出発点は `gravity-plus.html`（上＝候補のピルの帯／下＝落ちて積もる山）。

残っていた欠陥は **「山に落ちているものが説明できない」** ―― 提案もタスクも同じ形で
落ちるので、山が何の集まりなのか言葉にならない。

### §01 「山は何か」の5つの答え（未確定）
展覧会がどうなるかを各案に明記した。

| | 山の定義 | 展覧会は |
|---|---|---|
| A | やるべきこと | **入れない**。山はタスク専用。提案は別の器へ |
| B | 締切のあるもの | 会期の終わりが締切になるので**入れる**（会期末が近いほど下へ） |
| ★C | **自分の時間を使うと決めたもの** | **入れる**。行くと決めた時点で「自分の時間の使い道」になる |
| D | 今日という日に属するもの | 今日行くなら入る。土曜なら入らない（日が変わると山が入れ替わる） |
| E | 自分が引き受けたもの | 引き受けた＝入る。**Cとほぼ同義だが「義務」の匂いが残る** |

**★C を推す**。理由 ―― このアプリは時間管理ではなく
**「自分の時間をどう使うか」の提案**が主題なので、山の定義がアプリの主題と同じ言葉になる。

Cを採ると2文で説明が済む:
- **上の帯 ＝ まだ自分の時間を割り当てていないもの**
- **下の山 ＝ 自分の時間を使うと決めたもの**

- **角のある形 ＝ やるべきこと**
- **丸くて写真を持つ形 ＝ やりたいこと**

★これで「落ちるもの」は1文で言え、「違い」は**分類ではなく形**で見える。
種類でレーンを分けない（分けると山の無造作さが死ぬ）。

### §02 帯の改良4案（提案も同じ帯に流す。未確定）

- **03 窓が混ざる** … ピルの列の中に **150×118 の角丸の窓**が1つだけ混ざる。

- **04 写真だけの二段目** … 二段目は**変な形にマスクした写真のみ**（花・クローバー、78px）。

### §03 下ろしたときの3つの振る舞い（未確定）
展覧会を帯から下へ引いたとき。

## 第19便 — ふたつの日付（2026-09-06）
Artifact: https://claude.ai/code/artifact/dd8323be-8352-4bd9-a7b7-74a8ffdd403b

C案（山＝自分の時間を使うと決めたもの）を軸にすることでユーザー了解（まだ確定ではない）。
残った穴 ―― **帯にいるものは今日のものとは限らないのに、山は今日のもの**。

### ★混乱の正体（第19便で言語化）
日付が1つだと思っていたのが誤り。**日付は2つある。**

- **帯の日付 ＝ 見つけた日**（今日）。「今日見つけたおすすめ」「今日行ったらどう？」の**バナー**。
  日付は**中身ではなく帯そのもの**が持つ。だから帯の中身に日付が無くていい。
- **山の日付 ＝ やる日**（今日）。

したがって**下ろす手つきは2つの決断を同時にしている**（引き受ける ＋ いつ）。
2つ目をどこで聞くかが未解決だった。

**規則案**: **日付を聞く正規の入口は「下ろす手つき」1つだけ**。編集画面でも変えられるが、
入口を増やすと「どこで決めたか」が散ってまた説明できなくなる。

### §02 構造4案 — 今日でないものはどこにいるか（未確定）
- **S1 今日だけの山** … 今日でないものは落ちない。**帯に日付の札が付いて残る**（予約席、点線）。
  朝になるとひとりでに降る。強＝山の意味がぶれない。弱＝帯が「新着」と「予約」の2役
- **★S2 高さ＝日の遠さ** … 地面＝今日。明日は少し浮き、土曜はもっと高い。遠いほど薄く小さい。
  **毎朝ぜんぶ一段沈む**。強＝画面が上から下まで**1本の時間軸**になり「上＝未定／下＝今日」も
  同じ軸の続きになる。既存の浮力1行で作れる。弱＝宙のものが多いと散らかる（**3つまで**で解決）
- **S3 日ごとの引き出し** … 横スワイプで山ごと入れ替わる。強＝分かりやすい。
  弱＝**ふつうのカレンダーに近づく**。横スワイプがアプリ間の横スライドと衝突
- **S4 日付を持たない** … 山＝今週やると決めたもの。強＝手つきが1つで済む。
  弱＝**「今日」が消える**。朝ひらいて「まず何を」を画面が言わなくなる

### §03 手つき4案 — 日付をどう割り当てるか（未確定）
- **★G1 地面から曜日が生える** … 掴んだ瞬間、**地面から巨大な曜日が指に連れて伸びる**。
  指の下の1文字だけ墨で立ち、離すとその日へ落ちる。
  ★★**新しい語彙をひとつも足していない** ―― 既存の **TIMELINE**（上スワイプで曜日が伸びる）
  と同じ仕掛けで、**持ち上げると TIMELINE が半分だけ開く**と言える。**2つのモードが1つの動きで繋がる**
- **G2 日付のダイヤル** … 指の周りに日の輪。回して選ぶ。JOURNAL の録音ダイヤルと同じ材料。
  強＝親指1本で完結。弱＝輪が図形を隠す。**山と時間軸の関係を何も語らない**（ただの選択メニュー）
- **★G3 落下の途中でカードが開く** … 中の選択肢が**日付**。AI が会期から候補日を出すので
  **読む＝決める**が一体になる。**「いつ行くか自体が提案」のものだけ**これ。
  「返信する」に会期の話は無いので G1 でよい。**2つを使い分ける**
- **G4 深さ＝遠さ** … 下ろす距離が日付。S2 と対で**手つきと構造が同じ規則**になる。
  弱＝直感と逆。**S2 を採るなら向きは逆**（**持ち上げる＝先延ばし／下ろす＝今日**）が正しい

推し: **G1 を基本、会期のあるものだけ G3**。
