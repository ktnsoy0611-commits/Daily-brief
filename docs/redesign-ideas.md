## 0. 土台（第10便 案4 を採用・2026-09-06）

★ユーザー評価 …「**案4は、タスクの画面と AI の候補の画面がデザイン的にも UX 的にも
繋がっていて良かった**」。他の3案は「まとまっているようで統一していない／
**UI・UX 的なユニークさが足りない**」→ **却下**。

**採用した土台（＝ GRAVITY の世界の語彙だけで書く）**
- 世界は1つ。**ピル・図形・額縁・円**しか出てこない。カードもグリッドも持ち込まない。
- **候補（声から）＝ピル**。画面の上を横に流れ、画面外へはみ出す。
  **長押しして下へ引くと図形に変わって落ちる**＝そこで初めてタスクになる。上へ払えば捨てる。
- **フォローアップ＝山の中でいちばん大きい図形**（大きさ＝優先順位という既存の規則が効く）。
- **持ち物＝親の図形に寄り添う小さな円の列**（塗り＝済／輪郭＝未）。

**残っている問題（この一覧の主題）**
★★★**提案は「提案」であってタスクではない。同じ山に混ぜると意味が壊れる。**
いまの額縁の図形だけでは足りない。

## 1. 提案をどう置くか ── P1〜P12

**どれも「山と同じ画面に居るが、タスクとは別物だと形か物理で分かる」ことが条件。**

| | 名前 | 仕組み |
|---|---|---|
| **P1** | **浮く（浮力）** | 提案は**上へ浮く**。タスクは下へ落ちる。**同じ物理エンジンで重力の符号が逆**。画面の上半分に自然に溜まり、下半分がタスクの山になる。**混ざりようがない。** |
| **P2** | **吊るされる** | 天井から紐で吊り下がって静止している。**紐を切ると落ちてタスクになる。** 採用の操作が物理そのもの。 |
| **P3** | **地面になる** | 画面のいちばん下に提案が横一列に敷かれ、その上にタスクの山が積もる。**提案＝土台、タスク＝荷物。** タスクが減ると提案が見えてくる。 |
| **P4** | **奥の層にいる** | 提案は山の**奥**にあってぼやけている。二本指で押し広げるとピントが移り、提案が手前・タスクが奥になる。 |
| **P5** | **壁に貼り付く** | 画面の左右の縁に貼り付いていて、山とは接触しない。指で剥がすと落ちる。 |
| **P6** | **穴として在る** | 山の中に**色が抜けた穴**があり、覗くと写真が見える。**物ではなく場所**として存在する。 |
| **P7** | **背景の1枚** | 山の背後に全面の写真（デュオトーン）が1枚敷かれ、図形の隙間から見える。**今日の提案＝今日の地の風景。** |
| **P8** | **封をされている** | 閉じた封筒の形で山に混ざる。中身は見えない。タップで開く。**開くまでタスクと同格に扱われない。** |
| **P9** | **片付けると降ってくる** | 山が空に近づくと提案が上から降ってくる。**片付けた分だけ遊びが増える。** |
| **P10** | **隣の面（横スワイプ）** | GRAVITY の隣が提案の場。同じ物理だが**そこは「まだ自分のものではない」場所**。持ち帰るとこちらへ落ちる。 |
| **P11** | **振ると浮き上がる** | 画面を払う／端末を振ると、山の隙間から提案が浮き上がる。**普段は隠れている。** |
| **P12** | **額縁の図形（第8便A）** | 輪郭を内側へオフセットした額縁の窓に写真。**円と半円だけ**。※これ単体では足りないと判明済み。P1〜P11 との**組み合わせ材料**として残す。 |

★**私の見立て（未承認）** … **P1（浮力）** がいちばん強い。物理エンジンを1つしか使わず、
**「上＝外から来たもの／下＝自分のもの」が体で分かる**。P2・P3 が次点。

## 2. 形の変態（メタモルフォーゼ）── M1〜M8

★ユーザー着想（2026-09-06）…「**図形だったものがどこかへ持っていくとカードになり、
なめらかにカートゥーン的にアニメーションしてピル型になる**、そういうデザイン言語」。

| | 名前 | 中身 |
|---|---|---|
| **M1** | **状態＝形の対応表** | **ピル**＝まだ決めていない（候補）／**図形**＝自分のもの（タスク）／**額縁つき**＝外から来たもの（提案）／**カード**＝開いて読んでいる／**点**＝終わったもの（記録）。**5つの状態が5つの形。** |
| **M2** | **遷移は必ず連続変形** | 切り替えない。**輪郭が滑らかに変わる**（morph）。カートゥーン的に少し行き過ぎて戻る（既存の `lib/spring.ts` の減衰振動が使える）。 |
| **M3** | **タップ＝カードに開く** | 図形をタップすると、その場で**角丸四角のカードに変形**して詳細が現れる。閉じると図形へ戻る。**画面遷移が要らない。** |
| **M4** | **完了＝点に潰れる** | 終えると図形が潰れて点になり、**記録の列へ飛んでいく**。記録が図形の行き先になる。 |
| **M5** | **却下＝くしゃっと丸めて消える** | しわ紙の質感がここで効く。丸まって小さくなって消える。 |
| **M6** | **提案を採る＝額縁が外れる** | 写真の窓が閉じ、**色ベタの図形になる**＝自分のものになった。逆に「あとで」は額縁のまま浮いて戻る。 |
| **M7** | **候補の承認＝ピルが丸まって落ちる** | 引っぱると縦横比が変わり、丸まって図形になって落ちる（第10便 案4 で既に描いた動き）。 |
| **M8** | **週末＝点が集まって1枚になる** | 7つの点が合体して**1枚の幾何学ポスター**になる。★これは既存の未実装の主軸（`project_knowledge` §1「1日の終わりに3要素が1枚の幾何学ポスターへプレスされる」）と**そのまま接続する**。 |

★**M1 と M2 が決まると、他は全部そこから導ける。** 最初に見るべきはこの2つ。
